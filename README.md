# 玲 · QQ 风格模块 0.1.4

## 0.1.4 更新

改善模型连接检测的超时处理：连接超时由 6 秒调整为 12 秒，模型响应读取超时由 25 秒调整为 45 秒；模型信息查询仍为 10 秒。正常响应不会被额外延迟，也不自动重发超时的生成请求。网络失败区分连接、请求提交、等待响应、读取响应及 DNS/HTTPS 问题，并显示已耗时。

检测按钮分阶段显示进度，只有真实模型返回有效内容才报告连接成功；显示本次配置的结果，检测期间改过设置会提示重新检测。测试不写入聊天历史。双线程、预加载和网页风格输出路径保持不变。本轮手机真实 Java 检测成功，包含信息查询和生成共 17.7 秒；这是单次结果，不代表网络波动已消除。详见 [验证记录](VALIDATION.md)。

## 0.1.3 更新

自动回复的图片准备和模型生成改为固定两个工作线程，可同时处理不同会话；同一会话仍等待发送确认后才接受下一次回复，原有队列上限、冷却、30% 图片点评和总频率限制保留。开始生成时，网页引擎若空闲则提前打开当前风格页，与模型请求重叠等待。

预加载绑定账号、配置版本和所选风格，最多保留 60 秒，只使用一次；配置变化、加载失败或过期后丢弃。网页转换仍在主线程逐条处理，每条检查准确风格地址、输入和任务标识，不并行操作同一个页面，不复用上一条结果。网页输出原样发送，失败仍取消自动回复。实现及验证见 [提速说明](docs/REPLY_LATENCY-0.1.3.md) 和 [验证记录](VALIDATION.md)。

## 0.1.2 更新

修复自动回复没有保留当前风格：原先网页转换后还会交给通用模型再次改写；没有模型配置时，校对分支甚至直接返回转换前的普通回复。现在统一为「生成回答/点评 → 当前所选风格网页转换 → 原样提交 QQ」，正常回答、图片点评、私聊和戳一戳使用同一条最终输出路径。空白、过长或失败的网页结果取消发送，不回退普通回复；等待期间切换账号、风格或配置会取消旧任务。群聊引用和图片点评 30% 规则保持不变。

此修复同时移除了每次回复的一次串行模型校对请求。原始提速分析见 [回复耗时分析](docs/REPLY_LATENCY-0.1.2.md)；其中双线程与页面预加载已在 0.1.3 实现。

## 使用

通过 LSPosed 对 QQ 启用模块，或将 APK 嵌入现有 LSPatch QQ。普通安装模块 APK 只提供菜单预览，不能单独完成注入。QQ 中的「玲」悬浮图标在 3 秒未操作后自动向侧边收起，仅露出 12dp。点击收起的图标先展开，再点击打开控制菜单；菜单打开期间暂停收起计时。长按后拖动，松手自动吸附到最近的左右边缘，并记住侧边和相对高度。短按滑动不会误触菜单；切换页面、旋转屏幕及弹出键盘时重新约束位置。

界面沿用原脚本的粉白圆角风格：淡粉渐变标题、白色分组卡片、粉色单选状态、圆角输入框和按钮。设置页固定保留标题与关闭按钮；内容可滚动，更多设置按需展开。控件触控高度至少 48dp。

单页只选一种风格：

| 项目 | 状态 | 网页 |
| --- | --- | --- |
| 猫娘语 | 可选择 | https://yinglish.club/translators/貓娘語 |
| 雌小鬼（俏皮吐槽） | 可选择 | https://yinglish.club/translators/雌小鬼 |
| 病娇（角色语气） | 可选择 | https://yinglish.club/translators/病娇 |
| 淫语 | 可选择 | https://yinglish.club/translators/淫语翻译器 |

首次安装时「发送前转换」「自动回复」均关闭。启用前停止旧的 `LingCatGirl_Custom_V2` 脚本，并在其展开详情底部关闭「启动时自动加载」；仅停止运行会在下次启动 QQ 时重新加载。否则旧脚本仍可能提前处理消息，包括剥除 `/` 前缀。没有旧的双风格叠加、驯服模式或本地猫娘词语替换。

- `/文本`：跳过转换并发送 `文本`；`//文本` 发送 `/文本`；单独 `/` 保留。
- 仅改写单个普通文字元素，图片、文件、引用、混合消息和带 @ 的手写消息不改写。
- 黑名单按 QQ 号、群号或 UID 精确匹配，同时约束手写转换和自动回复；黑名单不阻止本人发送原文。支持空格、换行、逗号和分号。
- 可单独开关好友私聊自动回复；群聊必须加入群号列表，默认还要求 @自己。使用当前唯一选中的风格。
- 默认使用 Rinko 的 `deepseek-v4.1-flash`（`https://api.rinko.ai/v1/chat/completions`），支持自定义 HTTPS、OpenAI 兼容接口。先生成简短回复，再由当前风格网页转换；未配置 Key 或模型时使用设定的普通回复。DeepSeek V4.1 Flash 关闭思考模式以缩短回复等待。
- 「导入旧脚本」仅在 QQ 内可用，导入旧 API Key、模型、群号和黑名单，不自动开启功能，不迁移驯服或叠加风格设置。

## 网页引擎与数据

四个风格均使用上述站点的实际网页及翻译按钮。没有抓取未公开 API、复制其提示词，也没有宣称本地算法等同于上游。待转换文本会提交至 Yinglish Club；启用模型回复时，收到的文本还会提交至用户设置的 API。网页的可用性、限流、结果和行为受上游控制。遇到免费额度耗尽会明确报错；通过菜单「网页激活 / 查看授权」在 QQ 内访问官方激活表单，该页与转换引擎共享 WebView 授权状态。桌面浏览器的授权不会自动复制到 QQ。

WebView 串行队列最多 8 个等待任务，每个任务含排队最多 45 秒；每次使用独立页面，关闭文件/内容访问、混合内容、第三方 Cookie 和弹窗，没有原生 JavaScript 桥。遇到网络失败、网页验证或页面结构变化不会绕过验证：手写消息按原文继续提交；自动回复取消。不能保证网页风格输出字数或措辞完全固定。

发送钩子先记录原始 `/` 前缀，再在其他模块准备发送属性后决定是否异步转换；排队时复制元素列表和属性表，保留原消息 ID、联系人及回调。网页渲染进程退出时取消该任务，避免让渲染器故障直接终止 QQ。

后台接收通过 QQ 内核 `addKernelMsgListener`，同时接收新消息、入库和媒体消息通知，不依赖聊天界面。QQ 处于后台且自动回复开启时，每 30 秒至多调用一次 QQ 自身的消息同步入口（与 QQ 下拉刷新使用同一接口）；每 10 秒轮询最多 4 个已配置且不在黑名单内的群，每群通过普通会话查询接口仅查最近 10 条消息，群多时轮转；仅处理本次启动/开启后的新消息，沿用去重规则。该补查不扫描未配置群、私聊或完整聊天历史。开启自动回复时，配套 QQ 安装包启动本模块独立的前台服务，并显示「玲 · 自动回复运行中」常驻通知；关闭开关或点击通知的关闭操作会停止服务。每个处理任务持有最长 130 秒的 CPU 唤醒锁，结束后释放。后台运行会增加耗电，无法复活被系统杀死的 QQ，也不能保证网络断开或网页不可用时自动回复成功。

前台服务依赖配套 QQ 包中的非导出组件声明。仅在普通 QQ 上注入模块 APK，不会自动新增这个声明；界面会提示后台服务不可用。`tools/add-service.py` 为已有 LSPatch 外层清单添加这一独立服务，原 QQ、其他组件及权限保持原样；嵌入工具可接受该清单作为最后一个参数并验证写入内容。源码中不复用或改造 QQ 自身服务。

## 架构与边界

| 层 | 职责 |
| --- | --- |
| `core` | 单选风格、跳过规则、黑名单、时效、去重与单次提交保护 |
| `store` | QQ 私有目录、按账号分开设置、原子配置快照与修订号 |
| `engine` | 网页转换队列、自动回复 API、模型能力检测与图片编码 |
| `hook` | QQ 版本门禁、发送钩子、独立内核接收、账号检查、限速 |
| `ui` | QQ 内悬浮入口、单页控制、预览、显式旧配置导入 |

只处理 180 秒内的新消息；零 ID、历史导入、自发消息不自动回复。去重缓存 2048 条 / 5 分钟；每会话冷却 10 秒、同会话最多一个任务、全局每分钟最多发起 10 个回复任务。账号或配置变化会使旧自动回复失效；手写转换在配置变化后回退原文，在账号变化后取消。

自动回复仅在 QQ 发送回调返回成功后，将完整轮次保存在内存中；按接口、模型、密钥身份、QQ 账号、会话和发言人隔离，切换 QQ 账号或点击清空按钮时清除。全局历史存储估算预算 8MiB、最多 64 个会话，重启 QQ 后丢失；不会把聊天历史、图片或 API Key 写入日志。UI 内的「提交数」表示调用 QQ 提交接口次数，「QQ 确认」表示发送回调成功，均不代表对方已阅读。发送回调等待 20 秒，超时不会重发，避免重复消息。当前版本支持戳一戳回复，没有关键词规则。

群聊中每名发言人有独立记忆：优先使用已解析的 QQ 号，否则使用有效 UID，不使用昵称；无法识别发言人时跳过，不建立群内共享的「未知用户」记忆。同一个人在不同群也不共享上下文。每群的冷却和忙碌限制仍共同生效，用于控制消息频率，与上下文隔离无关。

可选的「保存本机诊断」默认关闭，只将阶段、计数、时间和屏幕状态写入 QQ 外部 files 目录的 `LingStyleDiagnostic.json`，不含联系人、消息正文或凭据。它用于在锁屏期间区分接收、模型、网页和发送阶段故障。

## 模型上下文识别

首次回复或点击「检测模型连接与上下文」时查询同一接口前缀的 `/models`。优先使用匹配模型的上下文字段；Rinko 当前列表只声明模型 ID，未提供上限，因此 `deepseek-v4.1-flash` 使用官方模型配置的 1,048,576 tokens，并在界面明确标记「官方模型规格（平台未返回上限）」。这不等于实测 Rinko 可以接收满 1M tokens。未知模型暂用 8192 tokens；若平台返回明确的更低上下文上限，则下调预算、裁剪历史并仅重试一次。

参考：[DeepSeek 官方模型配置](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/config.json)。缓存按接口、模型及密钥身份隔离，有效期最长 12 小时。对话预算预留系统提示、256 tokens 输出和 2048 tokens 余量；使用 UTF-8 字节数加消息开销作保守估算，而非精确 tokenizer。仅发送预算内最近的完整轮次；WebView 或发送失败不会提交到上下文。

「导入本机迁移配置」只读取 QQ 外部私有 files 目录中的 `LingStyleImport.json`，接受指定 Rinko 端点与 `model/key/groups/blacklist`，不启用自动回复，成功后删除迁移文件。此文件含凭据，不在源码或安装包中提供。日常也可直接在菜单中填写 API Key。

## 自动图像识别

自动回复支持当前消息中的普通图片、图片和文字混排，以及明确引用当前会话内历史图片的新消息；群号、好友、@自己、全局黑名单和发言人隔离规则仍生效。只收到一张图时也可理解后回复，结果继续使用当前风格。手写消息中的图片仍原样发送，不经过风格改写。

优先读取 `/models` 中明确的视觉能力或输入模态字段。平台没有提供时，在首次收到图片时自动尝试 OpenAI 兼容的 `image_url` 多模态请求，不凭模型名称猜测。成功后记录「接口已接受多模态请求」；明确的图片不支持错误会按接口、模型、密钥身份缓存 12 小时并跳过识图回复。鉴权失败、限流、网络异常、无效图片不会缓存成「模型不支持」。不会自动更换模型。

通过 QQ 自身的下载接口获取已获准回复的消息图片，每批图片下载等待上限 20 秒；当前图片和引用图片分别作为一批。仅读取 QQ 应用目录中的缓存，不把 QQ 图片 URL、下载凭据或原图 EXIF 发给模型。每条最多 2 张。已有可读的 QQ 原图缓存时直接使用，实际解码文件上限为 64MiB。需要下载且原图超过 12MiB 时，优先使用 QQ 已缓存的清晰缩略图，否则通过 QQ 请求 750px 缩略图，不主动下载超限原图；缩略图可能丢失小字等细节。最长边压缩到 1280px、压缩数据最多 768KiB；动图仅处理解码得到的一帧，不处理闪照、视频、文件或其他混合元素。任一图片获取失败或超过限制时整条跳过，避免假装已经看到完整画面。

引用图片按 QQ 消息标识或序号精确读取，只接受当前会话中的被引用记录；优先使用 QQ 的引用源消息接口，并将图片下载关联到当前引用消息；缺失时回退读取本地记录。不会扫描其他会话，也不把原发送者的聊天历史加入当前提问者的上下文。引用来源仍检查全局黑名单，历史引用优先使用已缓存的可读原图或清晰缩略图，否则请求 QQ 的 750px 缩略图；小字可能损失。原图片过期、不可下载或引用内容没有普通图片时跳过。当前图片与引用图片合计最多两张；图片下载前的引用记录查询最多两次，每次等待 6 秒。

压缩图片以 data URL 发往已配置的模型接口。如果最新图片处理失败，后续追问会提示该图片未能读取，不沿用旧图冒充新图。成功回复的原提问与压缩图片，以及已识别但选择安静或因点评冷却未发送的图片，只在内存中保留，后续文字追问可重新携带图片；按群及发言人隔离、按完整轮次裁剪。清空上下文会同步清除图片引用，旧请求完成也不会恢复已清空的历史。图片历史计入 8MiB 存储预算；上下文预算每图预留 4096 tokens，是保守估算，并非所有模型的精确视觉 token 数。接口接受图片格式不代表一定识别准确。

## 名单勾选与智能插话

在 QQ 内打开「黑名单与回复设置」，可点「勾选群聊白名单」「勾选好友黑名单」，按名称或号码搜索并勾选，点「保存勾选」立即生效。好友黑名单仍属于全局黑名单，适用于私聊及其群内消息；原有手动填写的群号、陌生人 QQ 号和 UID 保留。取消选择窗口不会修改配置，联系人列表仅在本机读取，不发送给模型。

「群聊仅回复 @自己」开启时保持原有行为；关闭后，未 @自己的群消息由模型判断为回答、自然点评或安静。明确 @其他人的消息直接跳过；图片分享不会被补成“请描述图片”的提问。安静结果不送入风格网页、不发消息，也不伪造已回复的历史。已成功识别的图片会按当前发言人保留为未回复的用户消息，让随后明确提问仍能接上；同样受账号、会话、模型身份隔离和内存预算约束。普通无须回应的文本不额外保存。模型未配置时不主动插话。

每会话发送后冷却 10 秒，全局每分钟最多判断 10 次；非 @消息每群每 10 秒至多判断一次。自然点评发送后，该群 60 秒内不再自然点评；模型判断为正常回答的提问和 @自己不受这条点评冷却限制。已有会话忙碌、发送冷却和总频率规则仍生效。

自动回复在内容生成阶段区分明确回答、自然点评和保持安静，再交给当前选中的官方风格网页转换。网页结果原样发送，不再交给通用模型改写。模型的语境判断以及网页自身的改写仍可能偏离原意；模块保证所选网页的输出不会被后续校对覆盖，并不承诺上游输出的语气、事实或措辞每次都准确。界面保留仅 @模式。

## 当前聊天页免打扰

「消息与回复」保留「当前聊天页面不自动回复」开关，默认关闭，与旧脚本一致；从旧脚本导入时继承该选项。开启后，仅跳过你正在前台查看的同一个群聊或好友会话，其他会话正常处理；离开聊天页、QQ 退到后台或息屏后按其余规则恢复。生成途中打开该会话，发送前会再次检查并取消本次回复。在前台被跳过的消息不在离开后补发。此选项不影响手动发送及风格转换。

页面识别直接监听 QQ 9.3.50 的聊天页显示/隐藏，并检查可见视图、Activity 生命周期和屏幕锁定状态，不依赖旧 QFun 脚本或残留的会话 Intent。模块菜单中的诊断显示检测是否安装、当前页面是否可见，不记录聊天对象标识。
